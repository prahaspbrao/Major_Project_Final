1. Executive Summary & Problem Statement

Modern software development relies heavily on large-scale code repositories containing thousands of source files, complex class hierarchies, and deeply nested dependencies. Navigating these repositories poses a steep learning curve for developers onboarding onto legacy projects or inspecting unfamiliar components.

Existing Limitations: Generic AI coding assistants (e.g., standard Copilot or ChatGPT) lack visibility into a project's private, non-public code structure. Conversely, traditional code search tools (such as grep or regex searchers) lack semantic natural-language comprehension and cannot synthesize code explanations, bug localizations, or refactoring recommendations.

Proposed Solution: The AI Developer Assistant for Code Repositories bridges this gap by combining Large Language Models (LLMs) with Retrieval-Augmented Generation (RAG). The system automatically parses code repositories into semantic blocks (functions, classes, modules), vector-embeds them, stores them in MongoDB, and executes grounded cosine similarity retrieval to answer natural-language developer queries with exact file paths and line number source citations.

Core Objectives Achieved
  • Objective 1: Parse, chunk, and embed source code repositories into a searchable vector index with line-level precision.
  • Objective 2: Retrieve relevant code snippets and generate grounded answers using LLMs / local RAG vector engines.
  • Objective 3: Provide a multi-mode chat interface supporting Code Explanation, Bug Localization, and Refactoring Suggestions.
  • Objective 4: Deploy a production-style architecture incorporating MERN, Redis caching, Nginx reverse proxy, and Docker Compose orchestration.

4. Complete Working Mechanism & RAG Pipeline

The Retrieval-Augmented Generation (RAG) workflow follows 5 systematic steps from repository scanning to grounded response generation:

Step 1: Semantic AST & Block Parsing

When a repository is indexed, chunkerService.js scans source files (`.js`, `.ts`, `.py`, `.java`, `.cpp`, `.json`, `.md`). It identifies function declarations, class definitions, and block structures, recording metadata including filePath, fileName, startLine, endLine, chunkType, and symbolName.

Step 2: Dense Vector Embedding

Each code chunk is passed to embeddingService.js, which extracts 64-dimensional feature-hashed term-frequency vectors (or uses Google Gemini `text-embedding-004` when an API key is configured). The normalized vector array is saved in the MongoDB CodeChunk document.

Step 3: Vector Similarity & Hybrid Retrieval

When a developer submits a query, ragService.js computes the query embedding vector and measures cosine distance against all indexed chunks for that repository:

Cosine Similarity = (Vector_A · Vector_B) / (||Vector_A|| * ||Vector_B||)

The algorithm applies a 30% keyword match boost for matching file paths and symbol names to ensure precise ranking.

Step 4: Grounded Answer Generation & Citation

The top-K matching chunks are assembled into a grounded prompt context. The RAG engine generates a markdown response containing explicit file paths, line ranges, similarity match percentages, and snippet previews.

Step 5: Redis In-Memory Response Caching

The backend checks Redis for key cache:rag:<repoId>:<mode>:<queryHash>. On a Cache HIT, the cached response is returned in <5ms with a ⚡ Redis Cache HIT indicator in the chat UI.
